# 产品 Brief · 体脂率测算（Body Fat Calculator）

> 版本：v1.9.0 ｜ 平台：Android（WebView 壳）+ 网页版（单文件） ｜ 仓库：https://github.com/kek2233/bodyfat-calculator

---

## 1. 一句话定位

**装在手机里的私人身体数据本**：一次录入身体围度就能算出体脂率，拍照即知一餐热量，所有数据与识别全部在本机完成——不注册、不联网、不上传。

## 2. 背景与问题

| 现状痛点 | 说明 |
|---|---|
| 体脂秤只给一个数 | 家用体脂秤误差大且不解释；健身 App 又常常"先注册、再开会员" |
| 记热量太麻烦 | 主流记热量 App 靠数据库搜索 + 手工称重，坚持不超过一周 |
| 隐私顾虑 | 饮食、体重、照片属于高敏感数据，用户不愿上传到云端 |
| 中老年/普通用户门槛高 | 复杂表单、英文界面、付费墙劝退 |

**机会**：现代手机算力足够在本地跑一个 10MB 级的食物识别模型；而"体脂率"这个数一旦有解释（等级 + 标准区间 + 计划），就能牵出完整的减脂闭环——测算 → 计划 → 每日签到 → 三餐记账 → 趋势回收。

## 3. 目标用户与场景

| 画像 | 场景与诉求 |
|---|---|
| **减脂中的普通人（核心）** | 想知道自己体脂到底多少、今天有没有吃超标；不想被复杂工具绑架 |
| **隐私敏感用户** | 不愿把体重/饮食/照片交给任何云端 |
| **无稳定网络 / 流量敏感用户** | 健身房、通勤地铁、境外旅行也要能用 |
| **想给家人用的人** | 单文件即可分享，无需账号体系 |

## 4. 解决方案与核心功能

| 模块 | 用户拿到什么 |
|---|---|
| **体脂测算** | 美国海军围度法（腰/颈，女性加臀）+ Deurenberg 公式法；男女分档给出体脂等级、脂肪重量、去脂体重、标准体重区间 |
| **拍照识餐（离线 AI）** | 内置 Food-101 MobileNetV2 ONNX（101 类），拍一张即出候选与热量，自动记入当前餐，可纠正/撤销；**照片不出手机** |
| **食物库** | 232+ 种中式食物（含主食/肉蛋/水产/蔬果/快餐/汤羹等 14 类），搜索 + 分类筛选 + 一键记餐 + 自定义增删 |
| **热量记账** | 按早/午/晚时间窗自动归类，过点未记显示「没吃」；环形进度显示摄入/目标，超标变红 |
| **计划 → 签到** | 按体脂区间与目标（减脂/维持/增肌）生成每日热量、三大营养素、餐单与七天训练；选定后该页直接变成每日签到（训练 + 三餐 + 饮水） |
| **数据统计** | 体脂率/体重双趋势（渐变面积折线）、近 7 天热量 vs 目标、签到完成率、今日三餐热量占比 |
| **数据自主** | 每次改动本机自动留快照可恢复；JSON 导出/导入（安卓写入「下载」目录）；一键清空 |

## 5. 差异化

1. **离线优先**：识别模型随包内置，首次识别无需联网、无需任何密钥；云端 AI 仅作为可选增强（用户自己填密钥）。
2. **零门槛**：无注册、无登录、无会员；安卓 6.0+ 直接装，网页版单文件双击即用。
3. **数据主权**：全部存于本机 localStorage，不上传；导出即拿得走。
4. **形态自由**：同一份 HTML 既是网页版也是 App 内页面，改一处两端同步。
5. **设计规范**：按开源 [apple-design-skill](https://github.com/naplesblue/apple-design-skill) 的纪律执行——统一表面 + 发丝分隔线 + 灰阶层级 + 单一强调色，玻璃只用于导航/弹层；底部导航为 iOS 26 液态玻璃滑动高光。

## 6. 技术架构与约束

```
┌─ Android 壳（Java / 无第三方依赖）
│   MainActivity：WebView + 原生桥（AI 调用 / 写入下载 / 特效开关 / 启动轨迹）
│   DiagActivity：诊断外壳（原生 UI 显示各步成败）
│   FileProvider：拍照取图
├─ 页面层（单文件 index.html，无框架、无构建）
│   设计令牌（浅/深色）→ 组件 → 页面渲染器 → 图表（内联 SVG）
└─ 识别层（按需加载，不拖慢启动）
    ort.min.js 540KB → ort-wasm-simd.wasm 10.5MB → mobilenet_v2_food101.onnx 9.8MB
```

| 约束 | 处理方式 |
|---|---|
| WebView 下 `fetch()` 不能读 `file://` | 内置 fetch 垫片：file 页面下的相对/绝对 file 请求统一走 XHR |
| 部分机型 GPU/滤镜崩溃风险 | 安全模式（软件渲染 + 关特效）自带崩溃自愈，仅"上次真崩过"时启用一次 |
| 低端机启动慢 | 推理引擎改为首次识餐才注入，启动零模型脚本解析 |

**实测**：模型加载 ≈ 0.5s，单次推理 ≈ 60ms；APK 11.7MB（已含模型）；minSdk 23 / targetSdk 34。

## 8. 关键指标（建议跟踪）

| 类型 | 指标 |
|---|---|
| 北极星 | **7 日留存**（连续 7 天至少完成 1 次测算或 3 餐记录） |
| 激活 | 首启 → 完成首次体脂测算的转化率；完成首个计划采用率 |
| 使用深度 | 日均记餐条数；识餐使用次数/周；签到完成率 |
| 质量 | 启动成功率、崩溃率、首次识餐耗时（目标 <2s）、包体大小 |
| 隐私承诺 | 出网请求次数（离线路径应为 0） |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 中餐识别准确率有限（Food-101 偏西餐） | UI 提供候选切换 + 一键撤销；鼓励自定义食物入库；可选云 AI 兜底 |
| 国产 ROM WebView 差异、机型兼容 | 安全模式 + 崩溃自愈 + 诊断包定位；启动零模型解析 |
| 体脂公式误差（围度法 ±3~5%） | 明确标注为估算并给出区间与趋势，而非绝对真值 |
| 用户数据只在本机 | 自动快照 + 导出/导入；提供"清空全部数据"入口 |
| 单文件架构的规模上限 | 现已 170KB；若继续膨胀可拆分为内联模块 + 资源外置 |
