# FitNote 系统设计规范 v2（Impeccable 版）

> 基于 [Impeccable](https://impeccable.style) 的美学原则，对 v1 做**品质升级**，不是重写。
> 设计上下文见 [`.impeccable.md`](../../.impeccable.md)。
> 兼容性：**主值用 OKLCH，全部附带 hex 回退**（老 WebView ≥ Chrome 50 也能正常显示）。

---

## 零、先回答：「更高级」到底是什么

不是加更多效果。v1 的问题也不是"不够花哨"，而是**没有性格**——它的色板经 OKLCH 拆解后暴露得很清楚：

```
v1 中性色  #F2F2F7 → oklch(96.3% 0.007  286)   ← hue 286 = 冷灰/蓝紫方向
v1 品牌色  #3ED17F → oklch(76.4% 0.170  154)   ← hue 154 = 绿
```

**中性色和品牌色朝相反方向偏**，所以整体是"一套标准灰 + 一个绿贴片"——这正是最容易被认成 AI 做的样子。

v2 的三件事：

| # | 从 | 到 |
|---|---|---|
| **1** | 冷灰中性色 + 单一绿 | **中性色整体朝绿色偏 150°**（chroma 0.004–0.014），色板内部自洽 |
| **2** | 纯黑 `#000` / 纯白 `#FFF` | 去掉极端值，最暗 `oklch(21%)`、最亮 `oklch(99.4%)` —— 真实材质没有纯黑白 |
| **3** | 大量 `rgba(...)` 透明度 | 全部换成**明确的实色**，透明度只留给焦点环与交互态 |

外加一条纪律：**强调色必须稀有**（视觉权重 10%），它才有力量。

## 一、色彩系统（OKLCH）

### 1.1 原则

- 用 **OKLCH** 定义（感知均匀，等值步进看起来等值）；**每个色都给 hex 回退**。
- 色相锚定 **H = 150（绿）**：品牌色、中性色共用同一色相方向。
- 越靠近黑/白，**彩度越低**（否则会脏）。

### 1.2 深色（默认外观）

| 角色 | OKLCH | HEX 回退 | 对比度 |
|---|---|---|---|
| 底 `ground` | `oklch(14.0% 0.008 150)` | `#070A08` | — |
| 表面 `surface` | `oklch(19.0% 0.010 150)` | `#111511` | — |
| 次表面 `surface-2` | `oklch(24.5% 0.011 150)` | `#1D221E` | — |
| 三级 `surface-3` | `oklch(30.0% 0.012 150)` | `#2A302B` | — |
| 一级文本 `t1` | `oklch(97.0% 0.004 150)` | `#F3F6F4` | **18.3:1** ✓ |
| 二级文本 `t2` | `oklch(75.0% 0.012 150)` | `#A9B0AA` | **9.0:1** ✓ |
| 三级文本 `t3` | `oklch(60.0% 0.014 150)` | `#7B837C` | **5.1:1** ✓ |
| **强调 `accent`** | `oklch(78.0% 0.170 150)` | `#56D57B` | **10.6:1** ✓ |
| 强调上的文字 | `oklch(20.0% 0.030 150)` | `#0C2313` | — |
| 分隔线 | `oklch(30.0% 0.012 150)` | `#2A302B` | — |

> 深色靠**表面亮度**分层（越高越亮），**不用阴影**。底绝不纯黑。

### 1.3 浅色

| 角色 | OKLCH | HEX 回退 | 对比度 |
|---|---|---|---|
| 页面底 `ground` | `oklch(96.5% 0.006 150)` | `#F1F5F1` | — |
| 卡片 `surface` | `oklch(99.4% 0.004 150)` | `#FBFEFC` | — |
| 次表面 `surface-2` | `oklch(94.0% 0.007 150)` | `#E8ECE9` | — |
| 三级 `surface-3` | `oklch(90.0% 0.008 150)` | `#DADFDB` | — |
| 一级文本 `t1` | `oklch(21.0% 0.012 150)` | `#141A15` | **17.4:1** ✓ |
| 二级文本 `t2` | `oklch(46.0% 0.014 150)` | `#535A54` | **7.0:1** ✓ |
| 三级文本 `t3` | `oklch(56.0% 0.014 150)` | `#6F7770` | **4.55:1** ✓ |
| **强调 `accent`** | `oklch(45.0% 0.130 150)` | `#00682A` | **6.9:1** ✓ |
| 强调填充（按钮底） | `oklch(52.0% 0.160 150)` | `#008130` | +白字 **4.9:1** ✓ |
| 分隔线 | `oklch(90.0% 0.008 150)` | `#DADFDB` | — |

### 1.4 语义色（4 个，各 2 档）

| 语义 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| 成功 / 完成 | `oklch(78% 0.17 150)` `#56D57B` | `oklch(45% 0.13 150)` `#00682A` | 已完成勾、达标 |
| 警示 | `oklch(80% 0.15 75)` `#F5B942` | `oklch(60% 0.15 70)` `#A96900` | 超量、注意 |
| 错误 / 破坏性 | `oklch(65% 0.20 25)` `#F2584A` | `oklch(50% 0.19 25)` `#C32618` | 删除确认、失败 |
| 信息 | `oklch(75% 0.13 230)` `#5AA9E6` | `oklch(50% 0.13 230)` `#0B6BA8` | 提示、说明 |

### 1.5 使用纪律

1. **60–30–10 是视觉权重不是像素占比**：中性 60% / 次要 30% / **强调 10%**。强调色一旦到处都是，就没有力量。
2. 强调色**不用于长正文**，也不做背景大色块。
3. **不靠颜色单独传达信息**（色盲 8%）：状态必须同时有图标/文字/形状。
4. 分类型数据（肌群、三餐占比）用**同色不同明度**，不引入第二个色相。

### 1.6 兼容性写法（直接可用）

```css
:root{
  /* 先写 hex 兜底（老 WebView 用这个），再写 oklch（新浏览器覆盖） */
  --ground:  #070A08;                 --ground:  oklch(14.0% 0.008 150);
  --surface: #111511;                 --surface: oklch(19.0% 0.010 150);
  --accent:  #56D57B;                 --accent:  oklch(78.0% 0.170 150);
}
```

## 二、排版系统

### 2.1 字体

**保留系统字体栈**——App 是离线单文件，外链 Web Font 会破坏"离线优先"和体积预算；且 Impeccable 明确指出：当 **性能 > 个性** 时系统字体是正确选择。

```css
--font-sans: -apple-system, BlinkMacSystemFont, 'HarmonyOS Sans SC', 'MiSans',
             'PingFang SC', 'OPPO Sans', 'Segoe UI', system-ui, sans-serif;
--font-num:  ui-monospace, 'SF Mono', 'Cascadia Mono', Menlo, monospace;  /* 仪表数字 */
```

**增强点**：给**数字**单独一条字体栈并开启 OpenType，让数据看起来像仪表而不是普通文字。

```css
.num, .metric{
  font-family: var(--font-num);
  font-variant-numeric: tabular-nums;   /* 等宽对齐，数字不跳 */
  font-feature-settings: 'tnum' 1, 'zero' 1;   /* zero = 带点零，区分 O 与 0 */
  font-kerning: normal;
}
```

> `zero`（slashed zero）是很少人用的细节，但对"重量 60 vs 6O"这种误读有实际价值。

### 2.2 字号（5 档，比例 1.25，用 rem）

| Token | rem | px | 字重 | 用途 |
|---|---|---|---|---|
| `--text-xs` | 0.75rem | 12 | 400 | 标注、元信息 |
| `--text-sm` | 0.875rem | 14 | 400 | 次要 UI、副文案 |
| `--text-base` | **1rem** | **16** | 400 | **正文（最低 16px）** |
| `--text-lg` | 1.25rem | 20 | 600 | 区块标题 |
| `--text-xl` | 2rem | 32 | 800 | 页面大标题 |

- **正文从 15px 提到 16px** —— 15px 低于可读下限。
- **全部用 rem**，尊重系统字体缩放。
- 只有 5 档，且相邻档差距 ≥ 12.5%，层级不再含糊。

### 2.3 垂直韵律（关键）

**正文 `16px × 1.5 = 24px`**，所有纵向间距取 **24px 的分数或倍数**：

| 场景 | 值 |
|---|---|
| 基线单位 | 24px（1.5rem） |
| 页面左右边距 | 1rem（16px） |
| 区块之间 | 1.5rem（24px） |
| 卡片内边距 | 1rem（16px） |
| 列表行高 | 3rem（48px，触控达标） |
| 紧凑间距 | 0.5rem（8px） |

> 文字和空间共享同一个数学基础，这是"看起来舒服但说不出为什么"的来源。

### 2.4 深色下的行高补偿

浅色文字在深底上**视觉更轻**，行高要加 0.05–0.1：

```css
:root[data-theme='dark']{ --leading-body: 1.6; }   /* 浅色是 1.5 */
:root[data-theme='dark']{ --body-weight: 380; }    /* 正文略降字重 */
```

## 三、空间与材质

### 3.1 空间节奏（不只用均匀间距）

- 均匀间距是"没节奏"的。**相邻区块用不同间距制造呼吸**：标题后 8px，区块间 24px，页面顶部 40px。
- **禁止万物皆卡片**：同组信息放同一张表面内用发丝线分隔（v1 已做对，保留）。
- **禁止英雄指标模板**作为唯一套路：不是每页都要"一个大数字 + 三个方块"。训练总结可以是，但记录页、食物库不该是。

### 3.2 发丝线与圆角

| 项 | 值 |
|---|---|
| 分隔线 | **0.5px** `var(--line)`，不再是 rgba |
| 卡片圆角 | 18px（内部控件 12px，胶囊 999px） |
| 描边 | 0.5px 实色 |

### 3.3 玻璃（用户指定的品牌记忆点，保留并收紧）

磨砂 `backdrop-filter` **只允许 4 处**：吸顶导航 / 底部 Tab 栏 / 弹层 / Toast。
内容区一律实色表面。

> 唯一例外：卡片可保留极轻阴影 `0 1px 2px oklch(0% 0 0 / 4%)` —— 它不是装饰，是承担"浮起"的语义。

## 四、动效

### 4.1 缓动：指数为主

```css
--ease-out-quart: cubic-bezier(.25, 1, .5, 1);
--ease-out-expo:  cubic-bezier(.16, 1, .3, 1);
--ease-in-out:    cubic-bezier(.65, 0, .35, 1);
```

| 场景 | 时长 | 缓动 |
|---|---|---|
| 页面切换 | 280ms | `ease-out-quart` |
| 弹层滑入 | 260ms | `ease-out-expo` |
| 按压反馈 | 160ms | 缩放 0.96 + 亮度微变 |
| 数值变化 | 300ms | `ease-out-quart`，不跳变 |
| 进度填充 | 400ms | 线性 |

### 4.2 一个例外（有意为之）

**底部 Tab 的液态滑动高光用弹簧 + 过冲**——这是 iOS 26 的形态语义，也是你指定的品牌记忆点。Impeccable 一般反对弹性缓动，但**有意图的例外不算 slop**；它只出现在这一处，其余全部指数缓动。

### 4.3 禁止

- 动画化 `width/height/top/left`（用 `transform`）
- 入场时整页飞入、循环播放的装饰动效
- 任何 ≥ 500ms 的动画

```css
@media (prefers-reduced-motion: reduce){ *{ animation-duration:.01ms !important; transition-duration:.01ms !important } }
```

## 五、文案

- **每个字都要有存在价值** —— 删除任何重复用户已能看到的信息。
  - ❌「今日已摄入 1240 千卡（目标 2600 千卡）」→ ✅「1,240 / 2,600 kcal」
  - ❌「点击此处开始你的训练记录」→ ✅「开始训练」
- 数字优先于形容词：**「容量 +38%」** 好过「进步很大」。
- 空状态要有**教育意义**：说明这个页面以后会有什么，而不是「暂无数据」。

## 六、AI Slop 自检清单（每次设计完逐条过）

| # | 检查 | 我们怎么答 |
|---|---|---|
| 1 | 这是纯灰 + 一个强调色吗？ | 中性色整体偏绿 150°（`.impeccable.md` 已固化为 anti-goal） |
| 2 | 用了纯黑/纯白吗？ | 无，最暗 21%、最亮 99.4% |
| 3 | 万物皆卡片？ | 同组信息合并，发丝线分隔 |
| 4 | 有英雄指标模板的套路感吗？ | 仅训练总结页用，其余各有版式 |
| 5 | 字体是默认 Inter/Roboto？ | 系统字体栈（离线约束下的有意识选择）+ 数字用等宽仪表字体 |
| 6 | 到处都是强调色？ | 视觉权重 10%，仅 CTA / 完成 / 选中 |
| 7 | 有霓虹发光/渐变光斑？ | 无，v1 的彩虹壁纸已移除 |
| 8 | 圆角 + 通用阴影堆出来的"现代感"？ | 阴影只有一处极轻，靠亮度分层而非阴影 |
| 9 | 别人会说"这肯定 AI 做的"吗？ | 靠**数字排版 + 绿偏移中性色**建立辨识度 |

## 七、v1 → v2 迁移清单

| # | v1 | v2 | 为什么 |
|---|---|---|---|
| 1 | `#000000` / `#FFFFFF` | `#141A15` / `#FBFEFC` | 纯黑白不存在于真实材质 |
| 2 | 冷灰 `#F2F2F7`(H286) | 绿偏移 `#F1F5F1`(H150) | 让中性色与品牌色同向 |
| 3 | `rgba(60,60,67,.75)` | 实色 `#535A54` | Alpha 造成对比度不可预测 |
| 4 | 正文 15px | **16px** | 低于可读下限 |
| 5 | 全部 px | **rem** | 尊重系统字体缩放 |
| 6 | 6 档字号（11.5/13/15/17/22/32） | 5 档，1.25 比例 | 11.5 与 13 太接近，层级含糊 |
| 7 | 无固定韵律 | **24px 垂直韵律** | 文字与空间共享数学基础 |
| 8 | 深色行高 1.5 | 1.6 + 字重 380 | 浅字在深底上视觉偏轻 |
| 9 | 深色底 `#0A0C0B` | `#070A08`（更深） | 与表面拉开层次 |
| 10 | t3 浅 3.02:1 | **4.55:1** | 达标 |

## 八、如果你想要「更大胆」

v2 是**克制的精致**。若你觉得还不够跳，可选方向（告诉我，我按这个重做一版）：

| 方向 | 做法 | 适合 |
|---|---|---|
| **精密仪器** | 数字改用等宽 + 单位小字 + 刻度线；页面像实验室仪表 | 强化"数据可信" |
| **杂志编辑** | 大标题紧凑无衬线 + 细分隔线 + 数据以表格排版 | 强化"记录本"的质感 |
| **工业实用** | 去掉圆角（4px）、实线边框、技术标签、警示橙作第二色 | 强化"器械/硬核" |

> 我推荐的方向是 **v2（克制）+ 精密仪器式的数字排版**——它最贴合"私人身体数据本"这个定位，也不与 iOS 26 玻璃冲突。
