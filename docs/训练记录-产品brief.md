# 产品 Brief · 训练记录模块（Training Log）

> 归属：**作为现有「体脂率测算」App 的第六个 Tab 合并上线**（不单独发 App）
> 定位补充：与既有「体脂 → 计划 → 签到 → 热量」链路打通，形成完整闭环
> 版本：brief v1（据此进入开发） ｜ 视频识别策略：**本地为主 + 可配云端兜底**

---

## 一、产品定位

面向**有固定健身习惯、重视训练数据记录的进阶健身者**，在现有体脂管理 App 内新增「训练记录」模块：

- **以「极速记录」为骨**——解决临时换器械、调重量、补录数据的操作成本
- **以「视频自动识别次数与动作」为翼**——解决"练完只剩视频、数据要靠手抄"的断层
- **以「多维度复盘」为收口**——周/月/年容量、肌群分布、PR 突破，让进步可见

一句话：**让一次训练从「练完就忘」变成「20 秒记完、月末看得见曲线」。**

### 为什么合并进现有 App 而不是另起一个

| 理由 | 说明 |
|---|---|
| 链路闭环 | 体脂率决定热量目标 → 训练消耗回写热量预算 → 签到里的「训练」项由训练记录自动置位 |
| 数据同源 | 共用一份本地数据库（体重、日期、签到、食物库），不重复登录/授权/导入 |
| 成本 | 复用已验证的底座：单文件页面 + Android 壳（崩溃自愈/安全模式）+ 离线模型运行时 + 构造与测试流水线 |
| 用户价值 | 减脂人群的「吃」与「练」本来就在同一场景里，切 App 就是流失点 |

## 二、目标用户与痛点

**画像**：每周训练 3–5 次，能自主安排训练计划，会拍视频复盘动作，已用训记/Strong/Hevy 中的至少一个，且对"手动录入"有明确不满。

| # | 痛点 | 现状 | 我们的解法 |
|---|---|---|---|
| 1 | **临时调整成本高** | 器械被占要重新搜动作、改预设重量组数，打断节奏 | 一键「同类替代」：按肌群给出可替代动作；重量**记忆上次 + ±2.5kg 步进**；整组「沿用上一组/上次同动作」 |
| 2 | **统计不够深** | 只有总容量，缺周/月/年拆解 | 周/月/年报告：肌群容量占比、容量趋势、PR 突破时间线 |
| 3 | **视频与记录脱节** | 拍了视频还要手抄数据 | 上传/选择训练视频 → **自动识别动作类型与次数** → 一键生成该动作的组记录，可手动修正 |
| 4 | **（新增）不想为记录付费** | 同类 App 把饮食/进阶统计放付费墙 | 全部功能免费；识别走本地，零订阅、零上传 |

> ⚠️ **范围声明（重要）**：视频识别覆盖 **动作类型 / 次数 / 组数 / 组间间隔**；
> **重量不做视觉识别**——从视频读片数与片重在实际拍摄条件下（角度、遮挡、光线）不可靠，行业亦无可用方案。重量走"记忆上次 + 步进微调"，这是可靠性最优解。

## 三、竞品分析

| 竞品 | 核心优势 | 核心劣势（=我们的机会） |
|---|---|---|
| **训记** | 动作库全、支持自定义计划、界面专业 | 手动录入繁琐、临时改计划成本高、饮食与进阶统计付费 |
| **Keep** | 课程体系与社区强 | 自定义记录弱，偏新手跟练，进阶诉求照顾不到 |
| **Strong** | 极简、无广告、容量记录顺手 | 无视频识别、可视化分析弱、无中文动作库优势 |
| **Hevy** | 社交与模板生态好、跨端 | 国内网络与支付门槛、离线体验一般 |
| **FitTime / 乐动力** | 国内用户基数 | 记录粒度浅，训练数据结构化差 |

**机会点收敛为三**：① 记录动作的**操作步数**（别人 5 步，我们 2 步）；② **视频→数据**的自动转化；③ **中文本地化的动作库与统计口径**。

## 四、核心差异化

1. **视频自动识别（动作 + 次数）**：上传训练录像，自动识别动作类型、组数、次数、组间休息，一键生成记录；识别结果可改可补。
   - 本地姿态估计模型（约 3–8MB，离线、无上传、无费用）；可选配置视觉大模型密钥作为兜底增强（会联网，与现有 AI 识餐同一套配置）。
2. **训练中零打断调整**：一键切换同类替代动作、重量步进微调，改动即时同步进本次训练与后续计划模板。
3. **多维度复盘**：周/月/年报告，拆解肌群容量占比、容量变化曲线、PR 突破历史，直接指出"这个月腿练少了"。

## 五、核心功能清单

### 5.1 训练记录（P0）

| 功能 | 说明 | 自动化程度 |
|---|---|---|
| 开始/结束一次训练 | 默认套用上次计划或模板；支持空场次临时记录 | 手动 1 步 |
| 组记录 | 动作 / 重量 / 次数 / 组数 / RPE（可选）/ 休息 | 重量记忆上次，次数可手输或识别 |
| **视频识别生成记录** | 选择视频 → 抽帧 → 姿态分析 → 输出「动作名 + 次数 + 组数」→ 一键落库 | 自动，可修正 |
| 手动补录与调整 | 改动作/重量/次数、删组、插入组 | 手动 |
| 同类替代动作 | 器械被占时按肌群给出替代动作，重量沿用比例 | 一键 |
| 组间计时与休息提醒 | 自动记录组间间隔 | 自动 |
| 计划模板 | 创建/编辑/套用模板；训练中的改动可选择是否写回模板 | 半自动 |

### 5.2 数据统计（P0）

| 功能 | 说明 |
|---|---|
| 基础统计 | 训练次数、总容量（重量×次数）、平均容量、训练时长、总组数 |
| 维度化分析 | 周/月/年报告；肌群容量占比（环形/堆叠条）；容量变化曲线；动作次数分布 |
| PR 记录 | 各动作最大重量、最大单组容量、估算 1RM（Epley），突破时间线 |
| 训练日历 | 月视图展示每日训练情况，支持打卡与备注 |
| 数据导出 | CSV / Excel（复用现有原生桥写「下载」目录） |

### 5.3 动作库（P1）

- 内置常用动作（按肌群分类：胸/背/腿/肩/臂/核心/有氧），含标准动作要点文本
- 自定义动作：名称、肌群、器械、默认组数次数
- 动作详情：历史重量/次数曲线、PR、最近一次记录

### 5.4 复盘增强（P2）

- 视频与记录关联：从某次记录直接回看当时视频
- 动作质量提示（基于关节角速度/幅度给出"幅度不足""节奏过快"等提示）
- 训练消耗估算（按容量与体重估算 kcal），回写当日热量预算

## 六、产品调性

- **视觉**：沿用现有设计系统——深色运动风（近黑绿底 + 单一亮绿强调色）、实心表面 + 发丝分隔线、玻璃仅用于导航/弹层；浅/深色可切（设置内「外观」）。
- **体验**：
  - 核心路径 ≤2 步：**打开即上次动作 → 点一下就记一组**；**选视频 → 出结果**。
  - 训练中场景：大按钮、单手可达、步进器不弹键盘。
  - 表格化数据优先（重量/次数/组数三列对齐、等宽数字），拒绝花哨装饰。
- **一致性**：新 Tab 与现有 5 个 Tab 共用底部液态玻璃导航与中间凸起主动作。

## 七、技术可行性与架构

```
现有底座（复用，已验证）
├─ 单文件 index.html（无框架无构建）+ 设计令牌（浅/深）
├─ Android 壳：MainActivity（WebView + 原生桥 + 崩溃自愈/安全模式）
│   └─ 新增桥：视频取文件（相册选择已具备）、导出 CSV（saveText 已具备）
└─ 离线模型运行时（wasm + file:// 垫片，实测加载 0.5s / 推理 60ms）

新增：视频识别管线
视频文件 → canvas 抽帧（8–12 fps）→ 姿态估计（本地 WASM）
        → 关节角序列平滑 → 周期峰值检测 → 次数
        → 静止间隔分割 → 组数
        → 规则/小型分类器 → 动作名（覆盖深蹲/卧推/硬拉/引体/推举/划船/弯举等常用 15–20 项）
        → 人工确认/修正 → 落库
```

| 决策点 | 选择 | 理由 |
|---|---|---|
| 姿态估计 | 本地 on-device（MediaPipe Pose / MoveNet 类，WASM） | 离线、免费、隐私；延续"照片/视频不出手机"的产品承诺 |
| 抽帧率 | 8–12 fps，分辨率降至 480p 级 | 数次数足够，算力占用可控（中端机可接受） |
| 动作分类 | 规则优先 + 可扩展小分类器 | 常用动作规则足够稳，避免为长尾动作引入大模型 |
| 重量 | **不做视觉识别**，记忆上次 + ±2.5kg 步进 + 片重预设 | 可靠性优先（详见二、范围声明） |
| 云端兜底 | 复用现有密钥配置：把 3–5 张关键帧交给视觉大模型，返回动作/次数估计 | 用户自选、自付费、可随时关闭；离线路径保持零出网 |
| 数据存储 | 复用 localStorage（结构化 + 自动快照 + 导入导出） | 与现有数据同源，免迁移 |

**性能预算**：单段 30 秒视频识别目标 ≤ 8 秒（抽帧 + 推理），期间显示进度；模型按需加载，不拖慢 App 启动。

## 八、数据模型（草案）

| 实体 | 关键字段 |
|---|---|
| `Exercise` 动作 | id、name、muscles[]、equipment、isCustom、tips |
| `Session` 训练场次 | id、date、startedAt、endedAt、planId?、bodyweightKg?、note |
| `SetEntry` 组 | id、sessionId、exerciseId、weight、reps、rpe?、restSec、**source: video/manual** |

## 九、关键指标

| 类型 | 指标 | 目标 |
|---|---|---|
| **北极星** | 周记录完成率（当周完成 ≥3 次有效训练的活跃用户占比） | 首月 ≥35% |
| 激活 | 开始记录 → 完成首次完整训练（≥3 个动作）转化率 | ≥60% |
| 效率 | 单动作记录耗时中位数 | **< 25 秒**（对标竞品手输 ≈60 秒） |
| 采用 | 视频识别使用率 / 识别结果采纳率（未修正直接落库） | 使用率 ≥25%，采纳率 ≥70% |
| 深度 | 连续记录周数、月报查看率、导出使用率 | 月报查看 ≥40% |
| 质量 | App 启动成功率、崩溃率、识别失败率、离线路径出网次数 | 出网 = 0（未配云密钥时） |

## 十、里程碑

| 阶段 | 内容 | 交付 |
|---|---|---|
| **M1 记录主干** | 训练场次、组记录、同类替代、组间计时、日历、基础统计、CSV 导出 | 可用版本（不含视频） |
| **M2 视频识别** | 抽帧 + 姿态估计 + 次数/组数自动识别 + 结果修正落库；模型按需加载 | 差异化功能上线 |
| **M3 复盘与打通** | 周/月/年报告、PR 卡片、动作详情曲线、训练消耗回写热量预算、签到联动 | 闭环完成 |
| **M4 增强** | 云端兜底识别、动作质量提示、视频与记录互链 | 体验加厚 |

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 视频识别准确率不足（角度/遮挡/画面抖动） | 用户不再使用视频功能 | 识别结果**可一键修正**；先做"次数准确"再谈动作名；提供"只数次数不判动作"的保守模式 |
| 本地姿态模型在低端机上偏慢 | 识别体验差 | 抽帧降频降分辨率；显示进度与可取消；模型按需加载不影响启动 |
| 动作种类长尾 | 识别不了的动作被吐槽 | 规则覆盖高频 15–20 项 + 手动选择兜底 + 自定义动作，绝不假装全能 |
| 与现有 App 体积叠加 | APK 变大（现 11.7MB） | 姿态模型按需分包/首次使用时加载；必要时提供"精简版"安装包 |
| 记录动作比预期复杂 | 失去"轻量"定位 | 用"最近动作一键复记"作为主入口，逐步引导，不做多级表单 |
| 数据只在本机 | 换机丢数据 | 自动快照 + 导出/导入（已有能力），首启提示备份 |
