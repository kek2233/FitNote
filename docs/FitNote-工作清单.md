## 第一部分：待你审批的决策项

这 7 项会显著影响工作量，**定了我才开工**。前 3 项我已按判断给出推荐。

### D1 ⭐ 信息架构：怎么容纳「训练」模块？（影响最大）

现状是 **5 个 Tab**：测算 / 记录 / 计划 / 热量 / 食物库。全域方案要求 **4 个 Tab**（今日/记录/计划/我的）。三个选择：

| 方案 | 做法 | 工作量 | 风险 |
|---|---|---|---|
| **① 现状 + 训练凸起**（推荐） | 保留 5 Tab 不动；**中间凸起按钮作为训练入口**（点开 → 开始训练 / 继续上次 / 训练历史）。训练历史并入「记录」Tab | **小** | 低——不动现有页面，不会把你已经习惯的操作路径打乱 |
| ② 四 Tab 重构 | 按 FitNote 方案重排：今日（测算+训练+饮食）/ 记录 / 计划 / 我的（食物库+设置+看板） | **大**（几乎所有页面都要动） | 中——改动面大，回归成本高，但最终形态最干净 |
| ③ 五 Tab + 训练做第 6 格 | Tab 栏塞 6 个 | 小 | **差**——6 格在 390px 宽下每个只有 62px，图标+文字挤不下，且违背"克制" |

> **我推荐 ①**：先让训练跑起来、能天天用；等你实际用一段时间、确认手感后，再决定要不要做 ②。**训练功能本身不依赖架构选择**，所以①不会白做。

### D2 ⭐ 食物库数据的许可（合规）

数据来自《中国食物成分表》，但**整理仓库没有 LICENSE**（GitHub 默认 = 保留所有权利），原书也是有版权的出版物。

| 选项 | 说明 |
|---|---|
| **① 保留 + 注明来源**（当前做法） | 非商业开源引用，已在 `THIRD-PARTY-NOTICES.md` 第 4 节如实登记；数据是独立文件，**随时可删**（删掉即回到 231 种）。若日后商业分发需自行取得授权 |
| ② 换 USDA FoodData Central | **CC0 公共领域**，零许可风险；缺点是中餐覆盖差（包子、油条这类基本没有） |
| ③ 保留但默认不随包分发 | 用户自行下载 `foods.json` 放入目录才启用；合规最稳，但普通用户用不上全量库 |

> **我推荐 ①**，并在 App 内保留"来源"说明。如你更看重零风险，选 ②。

### D3 视频识别范围（v1.1）

| 选项 | 说明 |
|---|---|
| **① 纯本地姿态估计**（推荐） | 开源姿态模型（MoveNet/MediaPipe，Apache-2.0）+ 自研判定层，识别**动作类型 + 次数 + 组数**；不上传、免费、无网可用。**不做重量识别** |
| ② 本地 + 可配云端兜底 | 默认本地；用户自填视觉大模型密钥可获得更强识别（会联网、自己付费） |
| ③ 暂不做 | v1.0 先把记录主干做扎实 |

### D4 底部导航形态 — 已定 ✅

**悬浮胶囊**（高 62px / 左右 12px / 距底 20px / 圆角 26px）。理由：你要的"液态滑动高光"只在悬浮形态下成立。

### D5 颜色方案 — 已定 ✅

**A：页面底 `#F2F2F7` + 卡片 `#FFFFFF`**（iOS 分组列表），色值已按 WCAG 实算校正。

### D6 引导步数 — 已定 ✅

**3 步**（欢迎 / 身体数据 / 选计划），带默认值、可跳过。

### D7 中央凸起按钮的职责

| 选项 | 说明 |
|---|---|
| **① 训练**（推荐，与 D1-① 配套） | 点开 = 开始训练。这是本产品最高频的"产生数据"动作，配得上 C 位 |

## 第三部分：验收门禁

每个阶段交付前必须全绿，**任一不过不交付**：

### 一票否决

1. **dex 类完整**（`class_defs_size` 与 javac 产出一致）← 历史事故项
2. **启动成功率 ≥ 99%**（真机冷启动）
3. **离线路径出网请求 = 0**
4. **训练记组 ≤ 3 次点击**
5. **无假入口**（界面上的每个入口都必须能用）
6. 全套测试零失败、零 JS 错误
