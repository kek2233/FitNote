## 一、总则

### 1.1 产品边界

**做**：训练记录 · 体脂管理 · 饮食追踪，三者数据联动。
**不做**：社区 · 成就徽章 · 好友排行 · 付费会员 · 账号体系 · 云端同步。

### 1.2 四条硬约束（任何功能不得违反）

| # | 约束 | 验证方式 |
|---|---|---|
| C1 | **离线可完整使用** | 飞行模式下全部核心功能可用；离线路径出网请求 = **0**（抓包计数） |
| C2 | **无账号、无云端** | 代码内不出现登录/同步入口；localStorage 之外无持久化 |
| C3 | **数据可带走、可清空** | 任意时刻可导出 CSV/JSON；可一键清空且不可恢复 |
| C4 | **不导出用户数据** | 照片本地处理完即丢；不上传任何用户内容 |

### 1.3 交付形态

| 形态 | 说明 |
|---|---|
| Android | 单文件 HTML + Java WebView 壳，手工 aapt2/d8 流水线产出 APK |
| 网页 | 同一份 HTML，双击即用；需全量食物库时用本地 HTTP 服务打开 |
| iOS（未来） | 同一份 HTML + 壳，不改应用层 |

## 二、技术架构

### 2.1 分层

```
┌─────────────────────────────────────────────────────┐
│ 外壳层（Java）  MainActivity                          │
│  · WebView 配置 / 安全模式 / 崩溃自愈 / 启动轨迹日志    │
│  · 原生桥：相机、文件导出、识别通道                     │
├─────────────────────────────────────────────────────┤
│ 桥接层（JS ↔ Java）                                    │
│  · window.AndroidAI.recognize(dataUrl) → 分类结果      │
│  · window.Android.saveText(name, text) → 下载目录      │
│  · window.Android.isSafeMode() → boolean              │
│  · window.Android.setGlassEnabled(bool)               │
│  · window.Android.onReady()  · window.Android.startupLog(msg) │
├─────────────────────────────────────────────────────┤
│ 应用层（单文件 HTML，无框架）                            │
│  · Store（localStorage）· FoodDB · PlanEngine          │
│  · App（渲染 + 路由）· LiquidGlass · Glider             │
├─────────────────────────────────────────────────────┤
│ 数据层  localStorage（键名见 §3.1）                     │
├─────────────────────────────────────────────────────┤
│ 模型层  onnxruntime-web + MobileNetV2(Food-101)        │
│  · 按需异步加载，启动路径不加载                          │
└─────────────────────────────────────────────────────┘
```

### 2.3 桥接接口契约

前端**只能**通过下列接口触达原生能力；新增接口需同步更新本文档。

| 接口 | 入参 | 返回 | 约定 |
|---|---|---|---|
| `AndroidAI.recognize` | dataUrl(string) | JSON 字符串 | 失败返回 `{"ok":false,"err":"..."}`；前端必须处理失败分支 |
| `Android.saveText` | name, text | void | 写入「下载」目录；名称冲突自动加序号 |
| `Android.isSafeMode` | — | boolean | true = 特效关闭 + 软件渲染 |
| `Android.setGlassEnabled` | boolean | void | 用户手动调用即视为授权，清除 force_safe 标记 |
| `Android.onReady` | — | void | 页面就绪上报，用于崩溃循环检测 |
| `Android.startupLog` | string | void | 启动轨迹，落盘两份（应用目录 + 下载目录） |

> 桥接方法**必须**包裹 try/catch：`window.Android` 在浏览器/网页版下不存在，不得因此报错。

### 2.4 构建流水线（手工 aapt2/d8）

```
[1/6] aapt2 compile  res/ → *.flat
[2/6] aapt2 link     --manifest AndroidManifest.xml -A assets -o base.apk
[3/6] javac          --release 8 -classpath android.jar -d classes  （全部 .java）
[4/6] d8             --release --min-api 23 --lib android.jar --output dex  $(find classes -name '*.class')
[5/6] zip            base.apk + dex/classes.dex
[6/6] zipalign -p 4 → apksigner (v1+v2+v3)
```

**三条强制检查**（每次构建后必跑，任一不过即禁止交付）：

| 检查 | 命令 | 期望 |
|---|---|---|
| ⚠️ **dex 类完整** | `dexdump -f x.apk \| grep class_defs_size` | **15**（javac 产出多少类就进多少类） |
| 对齐 | `zipalign -c -p 4 x.apk` | 通过 |
| 签名 | `apksigner verify x.apk` | 通过 |

> **为什么把 dex 类数写进门禁**：本项目曾因 d8 只收到 2 个 `.class`、dex 缺失全部内部类（`MainActivity$1`、`$AIBridge`…），导致 **v1.2.0 起连续多个版本「点开就闪退」**，且崩溃记录器本身也是匿名类、来不及安装，连日志都没有。这项检查就是那次事故的对策。

### 2.5 性能预算

| 项 | 预算 | 实测 |
|---|---|---|
| 冷启动到首屏可交互 | ≤ 1.5 s | — |
| 页面 HTML 体积 | ≤ 200 KB | 176 KB |

## 三、数据规范

### 3.1 存储键

| 键 | 内容 | 形态 |
|---|---|---|
| `bf_records_v1` | 体脂测算记录 | `[{id,ts,gender,age,heightCm,weightKg,waistCm,neckCm,hipCm,bf,bmi}]` |
| `bf_cal_v1` | 饮食记账 | `{"YYYY-MM-DD":[{id,name,grams,kcal,protein?,carb?,fat?,meal,ts}]}` |
| `bf_checkin_v1` | 每日签到 | `{"YYYY-MM-DD":{train,water,breakfast,lunch,dinner}}` |
| `bf_plan_v1` | 当前计划 | `{goal,kcal,protein,carb,fat,meals[],train[]}` |
| `bf_cfg_v1` | 用户配置 | 身高体重、三餐时间窗、单位、外观 |
| `bf_ai_cfg_v1` | 云 AI 配置（可选） | `{baseUrl,model,apiKey}` |
| `bf_user_foods_v1` | 自定义食物 | `[{id,name,kcal,cat,def}]` |
| `bf_backup_auto_v1` | 自动快照 | 最近 N 份全量导出 |
| `bf_theme` | 外观 | `auto` / `light` / `dark` |
| （v1.0 新增）`bf_train_v1` | 训练场次 | 见 §3.2 |
| （v1.0 新增）`bf_ex_v1` | 自定义动作 | `[{id,name,muscle,equip,type}]` |

**规则**：新增键一律加 `_v1` 后缀；读取时若解析失败**必须回落默认值**，不得抛错中断启动。

### 3.2 训练数据模型（v1.0）

```js
// 训练场次
Session = {
  id, date:'YYYY-MM-DD', startTs, endTs,
  planKey?,                    // 来自哪个计划日（自由训练为空）
  note?,
  sets: [ SetEntry ]
}

// 单组
SetEntry = {
  id, exId, exName, muscle,
  weightKg,                    // 自重动作为 0
  reps,
  done:true,
  isWarmup:false,              // 热身组标记
  ts,                          // 完成时间戳（用于组间计时）
  restSec?,                    // 本组结束后实际休息秒数
  source:'manual'|'video'      // 视频识别来源标记（v1.1）
}

// 动作
Exercise = { id, name, muscle, equip, type:'barbell'|'dumbbell'|'machine'|'bodyweight', alt:[exId] }
```

### 3.3 数据口径定义（评审 P1-11 落地）

| 指标 | 定义 | 备注 |
|---|---|---|
| **训练容量** | Σ(重量kg × 次数)，**仅正式组**（`isWarmup=false`） | 自重动作（weightKg=0）**不计入容量**，单独统计「自重组数」 |
| **PR 主口径** | 估算 1RM（Epley）：`1RM = w × (1 + reps/30)` | 用于跨重量×次数比较；仅正式组 |
| **PR 辅助展示** | 该动作的「最大重量」与「最大单组容量 w×reps」 | 三者同页展示，避免口径歧义 |
| **组间计时** | `Date.now()` 差值 | **禁止用 setInterval 累加**；切后台/息屏回来必须按真实时间差纠正 |
| **连续记录天数** | 从今日往前，每天至少 1 次有效记录（训练 ≥1 组 **或** 记餐 ≥2 餐） | 断一天归零；**补记昨日可计入** |
| **每日热量目标** | BMR(Mifflin-St Jeor) × 1.375 + 目标增减（减脂 −400 / 维持 0 / 增肌 +300） | 下限：男 1500 / 女 1200 |
| **训练消耗回写** | `≈ 体重kg × 时长h × 6.0`（力量训练 MET） | 计入当日配额；在界面上标注"估算" |
| **餐次预算分配** | 早 25% / 午 35% / 晚 30% / 加餐 10% | 动态推荐即以此为基准 |

### 3.4 备份与迁移

- 自动快照：每次启动后 24h 内至少 1 次全量快照，滚动保留最近 5 份；
- 手动导出：CSV（便于 Excel 分析）+ JSON（可完整还原）；
- 导入：校验结构版本号，不兼容时明确提示而非静默失败。

### 4.1 颜色（实测对比度，全部达标）

**深色（主）**

| 角色 | 值 | 对比度 |

**浅色**

| 角色 | 值 | 对比度 |
|---|---|---|
| 底 ground | `#F2F2F7` | — |

| 次表面 surface-2 | `#EFF0F2` | — |

**三条颜色纪律**

1. **只有一个强调色**。分类信息（肌群占比、三餐占比）用**同色不同透明度**，不得引入第二种颜色。
2. 强调色**不得**用于长正文。
3. 警示色仅用于破坏性操作与错误态，**不得用于强调**。

> 原方案中的 `#86868B`(3.62:1)、`#C7C7CC`(1.68:1)、`#34C759` 做文字(2.22:1) 均低于其自订的 4.5:1 标准，已替换为上表数值。

### 4.2 字体

统一用 **px**（原方案 pt/px 混用，已统一）。

| 角色 | 字号/字重 | 字距 |
|---|---|---|
| 大标题 | 32px / 800 | −0.8px |
| 页面标题 | 22px / 700 | −0.3px |
| 区块标题 | 17px / 600 | −0.2px |
| 正文 | 15px / 400 | — |
| 辅助 | 13px / 400 | — |
| 标注 | 11.5px / 400 | — |

- 字体族：`HarmonyOS Sans SC, MiSans, PingFang SC, OPPO Sans, -apple-system, ...`（依次回落）；
- **所有数字**（容量 / 重量 / 计时 / 热量）使用 `font-variant-numeric: tabular-nums`，保证等宽对齐。

### 4.3 间距 / 圆角 / 描边

| 项 | 值 |
|---|---|
| 间距栅格 | 8 的倍数：4 / 8 / 12 / 16 / 22 |
| 页面左右边距 | 16px（窄屏 ≤375 时 14px） |
| 模块纵向间距 | 22px |
| 卡片内边距 | 16px |
| 圆角 | 卡片 18px · 内部控件 12px · 胶囊 999px |
| 分隔线 | **0.5px** 发丝线（`rgba` 见 §4.1） |
| 标准按钮高度 | 48px（主操作 52–54px） |

### 4.4 材质与玻璃使用规则

**统一表面优先**：同组信息放**同一张实心卡片**内，用发丝线分隔——不拆成多张小卡（碎片化是头号敌人）。

**磨砂（`backdrop-filter`）仅允许出现在 4 个位置**：

1. 吸顶导航栏
2. 底部 Tab 栏
3. 模态弹层 / 底部弹层
4. Toast

内容区**禁止**使用玻璃、渐变背景、装饰性投影。

> 唯一例外：卡片可保留一层**极轻**阴影（`0 1px 2px rgba(0,0,0,.04)`）。它不是装饰，而是承担"卡片浮于页面之上"的语义；浅色下若完全禁用会导致卡片边界不清。

## 五、交互规范

### 5.1 手势边界（评审 P0-4 落地）

原方案中"左滑"同时表示三件事，必须按下面收窄：

| 手势 | 作用域 | 行为 |
|---|---|---|
| 点击 | 全局 | 切换 Tab / 进入详情 |
| **横向滑动** | **仅分段控件内部** | 切换分类（训练/饮食/体脂） |
| **列表行左滑** | **仅该行内部** | 编辑 / 删除（不触发页面切换） |
| **屏幕左边缘右滑** | 距左 20px 内 | 返回上一页 |

**Tab 之间不滑动切页**（iOS 原生 Tab 就不滑动）。禁用长按菜单（`-webkit-touch-callout:none`），长按仅用于「看同类替代动作」。

### 5.2 动效规范

| 场景 | 时长 / 曲线 |
|---|---|
| 页面切换 | 0.28s · `cubic-bezier(.32,.72,0,1)` |
| 弹层滑入 | 0.26s · 同上 |
| 元素递进出现 | 0.22s · 下往上淡入 |
| 按压反馈 | 0.16s · 缩放 0.96 + 透明度微变 |
| 数值变化 | 0.3s 平滑过渡，**不跳变** |
| 进度条填充 | 线性 · 0.4s |
| 加载 | 仅本地模型加载时出现；小型圆环居中，**无文字** |

**禁止**：无意义装饰动效、进入时的整页飞入、≥0.5s 的动画、循环播放的动效。

### 5.3 状态设计（评审 P1-10 落地）

每个页面必须定义这 5 种状态，**不允许只做成功路径**：

| 状态 | 要求 |
|---|---|
| **首次空** | 展示引导式提示 + 一个明确的主操作入口（不显示 0% 空环、不显示空表格） |
| **加载中** | 骨架或小圆环；**不得**出现"网络加载中"字样（与离线定位冲突） |
| **成功** | 正常内容 |
| **错误** | 说明原因 + 给出下一步动作（重试 / 改用手动 / 去设置） |
| **权限被拒** | 相机/相册被拒 → 不阻塞，直接提供「手动选食物」路径 |

具体到三个必做场景：

- **模型加载失败** → 提示"识别暂不可用"，并**直接展示手动搜索食物界面**（功能不中断）；
- **识别结果不对** → 结果页可一键改分类、改克数、撤销；
- **零数据的今日页** → 显示"今天还没有记录"+「开始训练」/「拍照记餐」两个入口。

## 六、隐私与离线

| 项 | 实现约束 |
|---|---|
| 出网请求 | 离线路径必须为 **0**；仅在用户**主动**配置云 AI 后，识别请求才允许出网，且界面上必须明示 |
| 照片 | 拍照 → 本地压缩 → 本地识别 → **原图丢弃**，不写入相册、不缓存 |
| 存储 | 仅 localStorage；不写外部存储（导出为用户主动行为） |
| 界面告知 | 启动页、录入页、导出页均标注「数据仅存本机，不会上传」 |
| 反模式 | 不出现：登录、注册、云同步、离线横幅、网络失败重试弹窗 |

| 项 | 规格 |
