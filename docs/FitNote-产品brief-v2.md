# FitNote 产品 Brief v2（开源版）

> 变更说明：v1 评审后重写。**目标形态为 GitHub 开源项目**，因此所有对外承诺以"陌生人能翻代码验证"为标准。
> 分期策略：**v1.0 记录闭环 → v1.1 视频识别 → v1.2 计划联动**（不再一次做全）

## 一、产品定位

**FitNote** —— 装在手机里的全场景私人身体数据本。训练、体脂、饮食三线数据在**同一台设备内**打通，形成「采集 → 计划 → 执行 → 反馈 → 调整」闭环。

- **离线自主**：识别、计算、存储全在本机；默认路径**零出网请求**
- **零门槛**：无注册、无登录、无会员，装上就能用
- **数据主权**：数据只在本机；可导出、可导入、可一键清空
- **开源**：MIT 许可，代码可审计——**因此不做任何无法被代码证实的宣称**

## 二、核心痛点

| # | 痛点 | 说明 |
|---|---|---|
| 1 | **数据割裂** | 训练、体脂、饮食分散在三个工具里，无法联动（今天练了多少→该吃多少） |
| 2 | **门槛高** | 主流 App 强制注册、诱导会员、核心功能层层设限 |
| 3 | **隐私风险** | 围度、餐照等敏感数据必须上云，用户无法掌控 |
| 4 | **计划僵化** | 固定计划遇突发（缺练/漏餐）即脱节，越用越没参考价值 |
| 5 | **场景受限** | 强依赖网络：健身房信号差、地铁无网、境外无流量时核心功能不可用 |

## 三、目标用户

- **核心用户**：有固定训练习惯、会自己安排计划的**进阶训练者**（懂容量/PR 概念，对"记录不畅"最敏感）
- **扩展用户**：减脂塑形的普通用户——**通过三档预设计划进入**，只接触"今天练什么、吃了多少"，不暴露容量/PR 等进阶指标
- **特定需求**：隐私敏感者、无稳定网络者、需为家人记录者

> ⚠️ v1 评审指出：把"普通人群"当核心用户与功能体系（容量/PR/肌群占比）自相矛盾。v2 明确**进阶为核心、普通用户走简化模板**。

## 四、功能体系

### 4.1 身体数据（体脂管理）

- **体脂测算**：海军围度法 + Deurenberg 公式，输出体脂率、等级、标准区间与区间建议
- **身体档案**：身高/体重/年龄/围度本地留存，可改、可回溯
- **趋势**：周/月/年体脂与体重曲线，叠加训练容量与热量曲线做对照

### 4.2 训练记录

- **极速记组**（v1.0 核心）：选动作 → 重量步进 → 次数 → 落库，**单动作记录目标 < 25 秒**；重量**记忆上次同动作数值**，只需 ±2.5kg 微调
- **组间计时**：自动记录组间间隔，可选 60/90/120s 倒计时提醒
- **同类替代**：器械被占时按肌群给出替代动作（沿用上次重量）
- **视频识别**（v1.1）：本地上传/选择训练视频 → 自动识别 **动作类型 + 次数 + 组数 + 组间间隔** → 一键生成记录，可修正
  > **范围声明**：**不做重量视觉识别**——从视频读片数/片重在实际拍摄条件下（角度、遮挡、光线）不可靠，主流同类产品亦均为手动。重量永远走"记忆 + 步进"。
- **复盘**：周/月/年容量、肌群占比、PR 突破时间线

### 4.3 饮食追踪

- **本地拍照识餐**：Food-101 模型（101 类）→ 中文名 + 热量，自动入当前餐，可纠正/撤销，**照片不出设备**
- **食物库**：内置 232+ 种中式食物（14 类），搜索/筛选/一键记餐/自定义增删
- **三餐时间窗记账**：按早/午/晚时间窗归类，过点未记显示"没吃"；进度环显示摄入与目标

### 4.4 计划管理

- **计划生成**：基于身体数据 + 训练经验 + 目标，生成训练与热量一体化计划（三档预设）
- **弹性调整（建议式，不自动改）**：缺练/漏餐时给出**建议 + 一键确认**，并在今日页说明原因
  > ⚠️ v1 评审指出：全自动改计划会让用户觉得不受控。v2 一律「建议 → 用户确认 → 生效」，并提供"本周不再建议"开关。
- **周度复盘**：每周汇总完成情况，输出周报并给出下周建议

### 4.5 联动规则

| 场景 | 规则 |
|---|---|
| 身体数据 | 作为计划基准；训练/饮食记录持续更新趋势 |
| 训练消耗 | 按容量与体重估算 kcal，抵扣当日热量配额 |
| 饮食摄入 | 反向调整次日训练强度建议 |
| 连续偏差 | 触发**建议式**计划修正（非静默改） |

## 五、用户流程

### 5.1 首次启动（压到 3 步内到首页）

1. **欢迎页**：品牌 + 隐私承诺（"数据只在本机，默认零联网"）→ 「开始使用」
2. **身体数据**：身高 / 体重 / 腰围，**均预填合理默认值**（如 170cm / 65kg），只需微调；生日默认 1995-01-01（可改）→ 直接下一步
3. **训练经验**：新手 / 进阶 / 专业 → 点选即进

> 三档计划推荐**移到首页一键采用**，不再阻塞首次进入。完成祝贺页保留但可跳过。
> ⚠️ v1 评审指出：原"无默认值 + 6 步"是最大流失点，v2 已改。

### 5.2 日常使用

1. 打开即进「今日」：当日训练任务 + 饮食目标 + 进度
2. 练完 → 记组（或 v1.1 后上传视频）；吃完 → 拍照或选食物
3. 实时更新进度与热量缺口
4. 数据自动进入看板与计划模块

## 六、交互框架（四 Tab）

| Tab | 职责 |
|---|---|
| **今日** | 当日目标总览、情境化快捷入口（饭点→拍照记餐，训练时段→记组）、进度、建议提醒 |
| **记录** | **时间线与历史**（今天/本周做了什么，点进去改）——不是多合一录入表单 |
| **计划** | 当前计划总览、建议确认、目标设置、休息日 |
| **我的** | 身体档案、数据看板、本地数据管理（备份/导出/清空）、设置 |

> ⚠️ v1 评审指出：把训练/饮食/体脂三套录入都塞进「记录」会退化成三合一表单。v2 把录入放到「今日」情境入口 + 中央凸起按钮（按时间智能默认）。

## 七、核心差异化（措辞已改为可验证）

1. **默认零出网**：识别与计算全在本机；**仅当用户主动配置第三方密钥后**才可能联网，且随时可关。
   *（原"零出网请求"与"可配云端兜底"矛盾，已修正口径）*
2. **零门槛**：无注册/登录/会员；安卓 6.0+ 直装；网页版单文件双击即用。
3. **全链路闭环**：训练、体脂、饮食三线数据同库互通，无需用户手动整合。
4. **建议式弹性计划**：调整可见、可确认、可撤销，不静默改动用户计划。
5. **极简 Apple 规范**：单一强调色，层级靠字重/字号/灰阶；**玻璃仅允许出现在吸顶导航 / 底部标签 / 弹层 / Toast，内容区一律实心表面 + 发丝分隔线**。

## 八、技术实现

| 项 | 方案 |
|---|---|
| 视觉底座 | **开源模型**：食物识别 = MobileNetV2 Food-101（ONNX）；动作识别 = 姿态估计（MoveNet / MediaPipe Pose 类） |
| 自研部分 | **判定层**：动作规则、次数计数、组数切分、体脂/热量/计划算法（**这才是自研，也是开源后值钱的部分**） |
| 架构 | 单文件页面（无框架）+ Android WebView 壳（Java）+ 本地模型运行时 |
| 按需加载 | 模型首次使用时注入，**不拖慢冷启动** |
| 性能目标 | 食物识别：加载 ≈0.5s / 单张 ≈60ms；**动作识别：30 秒视频 ≤8s**（抽帧 + 姿态 + 计数，带进度与取消） |
| 数据 | localStorage；自动快照 + 导出/导入 + 一键清空 |
| 包体 | APK ≤15MB（含模型）；冷启动 ≤1.5s |
| 兼容 | minSdk 23（Android 6.0+）；针对国产 ROM 提供安全模式降级与崩溃自愈 |

> ⚠️ v1 评审指出两点并已在 v2 修正：
> ① 不得再写"自研视觉模型"（开源后一览即穿）；
> ② 0.5s/60ms 是**食物识别单张**的数字，**不能**与视频管线混写。

## 十、核心指标

| 类型 | 指标 |
|---|---|
| 北极星 | **连续 7 天，每天至少 1 次有效记录**（训练 ≥1 组 或 记餐 ≥2 餐）——口径明确，不用"或"混淆 |
| 体验红线 | **单动作记录耗时中位数 < 25 秒**；冷启动 ≤1.5s |
| 采用 | 视频识别使用率、识别结果采纳率（未修正直接落库） |
| 质量 | 启动成功率、崩溃率、识别失败率 |
| 隐私 | **默认路径出网请求数 = 0**（可自动化断言） |

## 十一、风险与对策

| 风险 | 对策 |
|---|---|
| 中餐识别准确率有限 | 持续补中餐数据；提供手动修正与自定义食物入库；可选云模型兜底 |
| 视频识别不稳（角度/遮挡/抖动） | 结果可一键修正；先保"次数准确"再谈动作名；提供"只数次数"保守模式 |
| 国产 ROM 兼容 | 安全模式（软件渲染 + 关特效）+ 崩溃自愈 + 诊断包定位 |
| 体脂公式误差（±3~5%） | 结果页标注误差范围与估算性质，强调趋势而非绝对值 |
| 单文件架构规模上限 | 模块化按需加载；核心包保持轻量，扩展功能以可选模块提供 |
| **开源后承诺被打脸** | 所有宣称必须可被代码验证（本 brief 已按此重写）；许可与来源如实标注 |
