# FitNote 界面审查（improve-ui）

> 方法来源：`improve-ui` skill（严格只读产品源码；每条 finding 须通过 契约 / 运行时 / 修正 三证明）
> 审查对象：`体脂率测算.html` 渲染的产品界面
> 记录时 commit：`fa64f4a02f4d` · 审查时间：2026-10-14

## Design language

- **Audited surface:** 安卓 WebView 内的单文件产品界面（Tab：今日 home / 热量 cal / 记录 history / 计划 plan / 食物库 food）。以「热量 cal」为主查页面——它是唯一残留问题的页面。
- **Design sources:** `docs/FitNote-系统设计规范.md`（已接受并落地，§4 排版）、`README.md`（界面章节）。
- **Documented decisions:**
  - 规范 §4.2：「**所有数字**（容量 / 重量 / 计时 / 热量）使用 `font-variant-numeric: tabular-nums`，保证等宽对齐。」
  - README 界面章节：「`tabular-nums` 等宽数字」列为已实现的质感细节。
- **Governing owners and consumers:** 数字读数的既有实现为 `.hero-num` / `.hero-ring-in` / `.st-n` / `.rec-n` / `.macro-n`（均已带 tabular-nums）；消费页面为全部 Tab。
- **Explicit exceptions:** None documented

## Findings

| # | Problem | Evidence | Proposed change | Scope | Confidence |
|---|---|---|---|---|---|
| 1 | 主按钮（`.btn`）文字对比度不满足规范下限。 | **契约**：`docs/FitNote-系统设计规范.md`「对比度：正文 ≥4.5:1 · 大字号 ≥3:1」。<br>**运行时**：`.btn` 规则为 `background:var(--accent);color:#fff`（第 562 行）。实算白字 on accent：深色 `#3ed17f` → **1.98:1**、浅色 `#12b76a` → **2.62:1**，均远低于 4.5:1。<br>**后果**：主按钮是全 App 最主要的行动入口（开始训练 / 保存 / 确认），其文字在绿底上有效不可读——这是全站影响面最大的一处。 | 引入 `--accent-ink`（深色 `#06210F`、浅色 `#FFFFFF`）并令 `.btn` 用它；浅色同时把按钮填充改为 `--accent-fill: #008130`（白字 5.02:1），深色保持 `--accent` 填充配深字（9.09:1）。 | `.btn` 及主题 token，1 条规则 + 2 个变量 | High |
| 2 | 「热量」页面当日主读数未执行文档规定的等宽数字。 | **契约**：规范 §4.2「所有数字（容量/重量/计时/热量）使用 tabular-nums」+ README「tabular-nums 等宽数字」。<br>**运行时**：Playwright 实算 cal 页面，`.big` 元素渲染文本为「已摄入 0 kcal」，`getComputedStyle().fontVariantNumeric === 'normal'`；另有 `.fd-u`（如「水产 · 建议 120g」）同样为 `normal`。同一页面内 `.hero-num` / `.st-n` 等已正确返回 `tabular-nums`。<br>**后果**：这是当日最主要的热量读数，数值随记账由 0 → 1240 变化时字符宽度不一致，数字与右侧单位会左右抖动——规范写明此项正是为了「保证等宽对齐」。 | 给 `.big` 与 `.fd-u` 两条规则补 `font-variant-numeric: tabular-nums`，与既有 `.hero-num` / `.st-n` 保持一致。 | `体脂率测算.html` 内联样式表，2 条规则 | High |

## Improve first

**#1「主按钮文字对比度 1.98:1」** —— 两条 finding 都通过三证明，但 #1 影响面更大：主按钮是全 App 最主要的行动入口，而它当前的文字在绿底上实际不可读（规范下限 4.5:1，实测不到一半）。修正只需引入一个 `--accent-ink` 变量并切换一处 `color`，即可同时把深/浅两种外观拉到 9.09:1 与 5.02:1。

## 后续追加调查：液态玻璃「只有模糊、没有折射」

用户反馈「玻璃看起来不行」，深查后发现一个**长期存在的实现失效**（不属于本报告 §3 的 finding 门，因为它是实现缺陷而非设计契约违反，故单列于此）：

| 项 | 事实 |
|---|---|
| 现象 | 玻璃边缘的折射/色差几乎不可见，全画面变化像素仅 **0.57%**、平均差值 **0.31** |
| 根因 | **Chromium 的 `backdrop-filter: url(#svgFilter)` 不执行 `feDisplacementMap`**。实测把位移量 `maxDisp` 从 13px 调到 80px，渲染结果**逐像素一致**（变化像素恒为 4.21%，为截图采样噪声） |
| 影响面 | 此前 v1.2.0~v1.7.0 所有版本的「真折射玻璃」实际都只有 `blur()`，位移滤镜从未生效 |
| 处置 | 改用**纯 CSS 视觉等效**：`blur+saturate+brightness` + 棱边（顶边高光/底边内阴影/外描边）+ 极淡环向色散（mask 只留 1px 边框 + screen）+ 上棱折射亮带。改后实测平均差值 9.57（深色导航）~26.22（深色吸顶栏），并顺带把此前为实心板的吸顶栏也改为玻璃 |
| 遗留 | `LiquidGlass` 模块中的位移图生成代码（含 Kyant0 算法移植）在该浏览器环境下不被执行；已保留并加注释说明，未删除（以便未来浏览器支持时启用） |
